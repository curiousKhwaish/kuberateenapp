# KuberaTeenApp

**Read these, in order, at the start of every session:**

1. **`docs/PEDAGOGY.md`** — HOW this project is taught and built. This
   project belongs to a 15-year-old learning to build real software under
   a real competition deadline. Every session in this repo follows the
   teaching rules in that file, regardless of how a request is phrased —
   this is not optional default behavior, it's how this project runs.
2. **`BUILD_PLAN.md`** — WHAT gets built, in what order, and why. The
   single technical source of truth: competition rules, research,
   architecture decisions, the final 4-feature scope, the day-by-day
   schedule, and open items. If `docs/PEDAGOGY.md` disagrees with it on a
   technical detail, this file wins.

If a decision changes mid-session, update `BUILD_PLAN.md` in that same
session — it only works as a cold-start reference if it's kept current.

This is a separate, independent project from Setuh (a different repo on
purpose — see `BUILD_PLAN.md`'s opening section for why). Don't assume
anything from a Setuh session carries over here; these two files are the
whole picture.

## Reflections

- `reflections/understanding.md` — comprehension Q&A recorded after each
  completed task
- `reflections/daily.md` — one-line "did / understood" reflection at the
  end of each session
- `reflections/decisions.md` — a running log of major decisions
  (architecture, scope, product) made *during* a single long working
  session — not the planning-phase decisions, which live permanently in
  `BUILD_PLAN.md` instead
